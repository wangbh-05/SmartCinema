
# 遇到的问题

接下来我想分享两个我们在开发中遇到的问题。

第一个是 AI 智能选座。最开始，我们给每个座位计算六个维度的体验好坏分，再按用户偏好加权求和，选总分最高的座位。这个方案看起来直观，但是有一个根本问题：好坏分数没有保留方向。

以银幕距离为例，系统原本认为中后排通常最舒适，所以太近和太远都会得到低分。可是当用户说“我近视，想坐近一点”时，低分究竟表示太近，还是太远，系统已经分不出来了。此时即使我们让该维度得分降低，并提高这个维度的权重，推荐结果仍可能贴近最后排，而不是用户真正需要的靠前位置。

所以我们把六个维度改成了客观程度，而不是好坏判断。比如银幕距离从第一排到最后一排取零到一百，价格从无附加费到最高附加费取零到一百。AI 负责把用户的话理解为一个理想的六维目标，以及每个目标的重要性；本地代码则在满足库存、连座和无障碍等规则后，选择与这个目标的加权欧几里得距离最小的座位。这样，所有的需求在六维映射中都能被清楚表达。

第二个问题是移动端滑动选座。早期我们一直调不稳定，核心原因是浏览器滚动、Canvas 点击和缩放手势会争夺同一次触摸事件；而且缩放后，手指位置和座位布局的位置也不是同一个坐标系。

最后我们把交互改成了显式的手势状态机。手指从可选座位开始滑动，就进入连续选座；从空白处开始滑动，就平移座位图；两根手指同时触摸，就切换为缩放。实现上，我们统一把触摸点换算到当前视图坐标，拦截默认手势，并抑制触摸结束后可能多出来的一次点击。
